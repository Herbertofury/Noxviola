# Project continuity decisions

## 2026-10-27

- Noxviola is a project-memory and task index only. Deliverables remain in their respective repositories.
- Progress should continue beyond individual checkpoints while useful authorized tasks remain. Hourly release checks are not a substitute for implementation work.
- AoA concept art, source-faithful behavior, animation and native testing are distinct acceptance gates. Preserve prior concepts as versioned alternatives where requested.
- Blast Cannon and Blast Barrel are different weapons. Blast Barrel uses the requested triangular three-barrel concept.
- Boom Boom's pig and creeper-pig nods belong in optional charms and stickers rather than being confused with the main weapon.
- Atlas remains project-neutral. Newest and Rust-first preferences are hypotheses to test, not universal rankings.
- Collection uses permitted public APIs/players and legitimately authorized data. SteamDB is reference-only. Autoplay defaults off.
- Authentication, native compatibility and performance claims require actual evidence. Keep incomplete and blocked states visible; never equate a browser session with an API grant.
- Preserve backups and working versions unless the specific deletion is approved. Do not broaden persistent access or incur costs merely to clear a task.

## Every-weapon quality requirement · 2026-10-27

Every AoA weapon needs outstanding exterior visuals and functioning, animated game internals comparable to a strong TaCZ pack. Start from a suitable licensed similar weapon base or rough mesh when it accelerates quality; inventory and verify reuse rights before copying. Refine coherent part motion, supply/resource continuity, hand fit, reload or recovery interruptions and confirmed-shot timing. These are fictional game implementation requirements, not real-world manufacturing instructions. A pretty concept, mesh export or numerical clearance check alone does not complete a weapon.
