# Opera GX and Firefox sidebar investigation — 2026-11-16

This is a partial source and synthetic-profile investigation, not a claim of complete sidebar parity. The owner's browser profiles were not inspected or changed. The work preserves the full four-browser goal and the remaining gaps in `browser/capabilities.json`.

## Installed source and resource evidence

- **Firefox 160.0**, build `20261104181552`, source stamp `d84e7a6936554efe26097d9d9b24a0e11330e630`: the installed `browser/omni.ja` SHA-256 is `e0e1a43a8b6749145a1d744086090da97a2f37a6c516e880f436f11a5313e002`. Its actual shipped `browser-sidebar.js` registers the built-in and extension panels and separates the launcher, current panel and navigation state. `SidebarState.sys.mjs` records panel command/open/width separately from launcher visibility/expansion/width. The shipped sidebar stylesheet defines different entry, exit and switch transitions; the controller skips them for reduced motion and handles interrupted transitions. Firefox's code is MPL-2.0; Noxviola's implementation is independent and does not copy Firefox telemetry. The [file-level hashes and source trace](https://drive.google.com/file/d/1DWGN1JvkGf92qFe9guOBTFGgwLCNK-0N/view) and [synthetic Firefox runtime receipt](https://drive.google.com/file/d/1lEvtTaJUIGYdRWo4VJneZ75UxtlzCUP7/view) are retained.
- **Opera GX 139.0.6053.42**: the installed `opera.pak` SHA-256 is `cbc8019a1d7e2c70e69cd5935797243b9f58b88b81bb4f1938e663604a88233f`. Its shipped sidebar setup bundle (resource 62122, decoded SHA-256 `3950b20a334fd621e289b0a371a76b4654335259525c39e32d5ce6aefdfe4103`) invokes privileged sidebar, custom-site and workspace APIs. Other shipped resources describe item routing, state and settings. A synthetic profile exposed workspace, GX feature, AI, messenger, social, special-feature, tool, extension and settings categories; changing History visibility survived reload. These are scoped observations in the [Opera receipt](https://drive.google.com/file/d/1VUbyKshysnCQgQ2cnae530yw5Gh-4eg9/view). The native controller is compiled in proprietary binaries; its source and internal control flow were not available, and its privileged APIs are not Electron APIs.

The synthetic Firefox controller test used a fresh profile and loopback-only Marionette: in horizontal mode the toolbar showed a roughly 40px launcher and hid it on the next toggle; selecting History opened the real History panel. A separate vertical/right test measured an expanded launcher near 239px and a collapsed launcher near 50px. This did not inspect an owner profile or prove physical-input, accessibility or frame-time parity.

## Current Noxviola behavior and gaps

| Capability | Evidence and remaining work |
| --- | --- |
| Launcher, left/right placement, panel width, saved open state | Implemented with separate saved controls. The launcher can expand to show labels or collapse to icons, independently of its panel, and retains that choice across restarts. Synthetic-profile tests exercised panel pointer/keyboard resize, rapid open/close and expanded right-side launcher geometry with vertical tabs and split pages. Hover expansion, auto-hide variants, customizable expanded width and full reference configurations remain open. |
| Workspace launcher | A configurable sidebar section switches through the existing workspace service, displays workspace colors, opens workspace management and restores each workspace’s last selected tab when available, including after restart, and otherwise selects a remaining tab. Drag ordering, workspace-specific icons and all Opera workspace behaviors remain open. |
| Tabs, bookmarks, history, downloads | Connected to the existing browser services and selected identity; the sidebar exposes searching and opening records and basic live download controls. Reference context menus, folder navigation, synced tabs and every variant remain incomplete. |
| User-added websites | A sandboxed real `WebContentsView` uses the selected identity's session; local two-identity storage isolation was exercised. Discord and ChatGPT documents loaded without signing in. This is a generic website panel, not full messenger, music or AI integration. Sandboxed sign-in popups use the panel identity, display their current origin and retain their opener. A generated local flow tested opener messaging, an about:blank-to-site navigation, identity storage isolation and popup cleanup on unload. Provider login flows, notifications, badges, explicit AI page context, and media service controls remain open. |
| Customization | Built-in tools can be shown/hidden and reordered; custom websites can be added, removed and reordered. An opened website may supply a real favicon for its launcher button; icons are kept in memory per identity, and unopened sites are not contacted for icons. Manual per-item icons, persistent icon caching, global mixed ordering, pin/auto-hide modes and migration from the source browsers remain open. Closing a website panel keeps it alive; its Unload control destroys that view. |
| Accounts & identities | The sidebar exposes the existing identity-scoped Account Atlas and its identity switcher. This is non-secret metadata and website routing, not a password manager. Firefox password storage, autofill, import/export and OS reauthentication remain open; see `FIREFOX-PASSWORD-SIDEBAR-2026-11-16.md`. |
| Extensions | Firefox `sidebarAction`, Chromium side-panel APIs, Opera sidebar extensions, and sidebar extension content-script behavior are not qualified or claimed. |
| Motion | Noxviola now uses the installed Firefox sidebar’s observed 230ms/190ms panel and 200ms/160ms launcher timings with its emphasized cubic-bezier curve, while honoring reduced motion and reversible transitions. The architecture differs from Firefox’s view transitions, so identical smoothness is not established. An earlier local headful synthetic-page sample toggled History 12 times at 250ms intervals. Noxviola shell `requestAnimationFrame` intervals had median 6.9ms, p95 7.1ms, maximum 11.0ms over 436 intervals; Firefox 160 chrome had median/p95 6.94ms, maximum 13.89ms over 430 intervals. These measure JavaScript frame callbacks, not compositor presentation or equivalent internal work; they do not prove equal smoothness, performance or superiority. [Noxviola receipt](https://drive.google.com/file/d/1h-F6CVo59AGZC0OYCouC6NCFyw4Odbqd/view); [Firefox receipt](https://drive.google.com/file/d/1giT57EBaqDQZGbYl3xyL3Oso1n5VBmPP/view). |

The real Noxviola source-app native gate covered the sidebar's history, bookmarks, two identity sessions, interruption and width changes alongside the existing browser workflows. Public-site observations established only that Discord and ChatGPT documents loaded in sandboxed panels; they did not use accounts or establish complete site compatibility. The [scoped native receipt](https://drive.google.com/file/d/1wRPy5HzD2U_UGnAroIL99lr_pRFt-3-z/view) and [public-page observations](https://drive.google.com/file/d/1qSFyZ27FMLG4V4Pb_6u_3cBauZdFsIIF/view) are retained. Complete Opera GX + Firefox sidebar parity remains an open acceptance gate.
