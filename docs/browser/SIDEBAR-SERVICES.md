# Sidebar services

Open the sidebar and choose **Passwords**, **Media player**, **Notifications**, or **Extension panels**. Sidebar settings control which tools appear and their order. Search Settings for “autofill” or “notifications” to open the corresponding tool.

- **Passwords.** Unlock the local store, add a login, or read the sign-in fields from the current tab and review them before saving. Choose **Fill** to populate the active tab's sign-in fields. The saved identity and exact HTTPS origin must match. HTTP loopback is supported for development. Noxviola refuses ambiguous and marked registration fields, checks document identity across asynchronous operations, and leaves form submission to the user. Reveal requires confirmation. Lock, close, or switch identities to clear the visible secret.
- **Media player.** Find actual HTML audio and video in tabs or website panels in the current identity. Play, pause, seek in available ranges, change volume, mute the element or mute its page. Website panels can keep playing when closed. **Unload** ends their native view. Media controls currently cover page frames and open shadow roots. They do not provide provider queues, DRM support, Web Audio graph controls, or Media Session next/previous commands.
- **Notifications.** A website can request permission from a tab or a sidebar panel. Allow once, make a durable choice, or block it. The Notifications panel lists current identity decisions and can forget each one. Windows controls toast visibility. Delivery evidence uses the browser's `Notification` show event and does not cover toast clicks, provider unread badges, or push delivery.
- **Extension panels.** An enabled extension can run a verified packaged `sidebar_action` or `side_panel` page in its installed identity. Panel JavaScript and native extension storage execute normally. The authenticated bridge handles packaged page and title changes, scoped options and supported open/close commands. Opening through an API requires an eligible gesture. Disable or uninstall to stop the panel. Remote Firefox panels, sidebar icons, the Firefox browser stylesheet, extension panel lifecycle events, and full marketplace compatibility have separate acceptance work.

The password store uses Electron `safeStorage` and persists a ciphertext envelope, including encrypted usernames and origins. Windows uses the signed-in OS account via DPAPI. Unlock is an application control. Windows Hello, a primary password, automatic form capture/fill, imports, password generation/health, address/card autofill, and sync require separate work. Keep the OS account and any profile backups private. Accounts & identities remains a separate metadata tool.

The source gate exercises the sidebar workflows with synthetic credentials and isolated profiles. It covers Windows password encryption and restart, real audio playback and controls, native notification permission and show, and execution and revocation of declared extension documents. The notifications and DPAPI runtime fixtures run on Windows. The per-feature inventory retains the outstanding reference-browser behavior.
